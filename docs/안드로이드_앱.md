# 시험장 신호 로거 (안드로이드) — 모의시험 실측용 프로토타입

감독관 폰으로 주변 **블루투스(BLE) 광고 신호와 Wi-Fi 신호의 세기**를 기록하고, 시험 중 기준선에 없던 새 신호가 반복되면 알려주는 앱.
시뮬레이션(`sim/`)의 가정을 **실제 기기로 검증**하기 위한 1차 도구이며, 실제 수능 현장 투입용이 아니다.

> ⚠ 이 앱은 로컬 환경에서 컴파일하지 못했고 **GitHub Actions(`android.yml`)가 빌드·단위 테스트한다.**
> 실제 폰에서의 동작(스캔 주기, 기기별 차이)은 아직 확인되지 않았다.

## 설계 원칙
- **외부 통신 불가**: `INTERNET` 권한을 선언하지 않는다. CI가 병합된 매니페스트에 이 권한이 없는지 매 빌드마다 검사한다.
- **수집 항목**: 시각, 관측자 이름, 내 위치 태그, 신호 종류(BLE/WIFI), 기기 ID(세션 키로 해시한 8자리), RSSI, 제조사 코드/주파수.
  기기 이름, SSID, 원본 MAC, 통신 내용은 **저장하지 않는다**.
- **저장 위치**: 앱 전용 폴더의 CSV. 시험 종료 후 USB로 회수한다(네트워크 전송 없음). 앱의 "로그 파일 삭제" 버튼으로 지운다.
- 화면 상단에 네트워크 연결 / 비행기 모드 경고를 표시한다(시험 중 감독관 폰은 외부 통신 금지).

## 설치
1. GitHub 저장소 Actions 탭 → "Android build" 실행 → `signal-logger-debug-apk` 아티팩트 다운로드(디버그 APK).
2. 감독관 폰(안드로이드 8.0 이상)에 설치(출처를 알 수 없는 앱 허용 필요).
3. 첫 실행 시 권한 허용: 위치(OS가 BLE/Wi-Fi 스캔에 요구), 근처 기기 / 블루투스 스캔.
   위치 정보 자체는 저장하지 않는다.

## 사용 절차 (모의시험 실측)
1. 폰: 비행기 모드 켜기 → Wi-Fi와 블루투스만 수동으로 켜기(네트워크에는 연결하지 않기).
2. 모든 폰에 **같은 세션 키**를 입력하고 관측자 이름(교실1~3, 복도1~3)을 정한다.
3. **① 기준선 수집**: 시험 전 교실을 한 바퀴 돌며 정상 신호(공유기, 감독관 기기)를 기록.
4. **② 시험 감시**: 시험 시작과 함께 전환. 이동할 때마다 격자에서 **현재 위치**를 눌러 기록한다.
5. 새 신호가 가까운 세기로 3회 이상 반복되면 진동 + 알림(`단서일 뿐 증거 아님`).
6. 종료 후 **중지** → USB로 CSV 회수 → 분석:
   ```bash
   node tools/analyze_logs.mjs exam-교실1-*.csv exam-교실2-*.csv exam-복도1-*.csv
   ```
   기준선에 없던 기기를 활동량 순으로 보여주고, 위치 태그와 RSSI로 후보 좌석을 추정한다.

## 시뮬레이션 가정 검증 프로토콜 (권장)
알려진 위치에 **테스트용 기기**(본인 폰 핫스팟, 이어폰, 워치 등)를 두고 다음을 기록한다.
1. 연결 상태별(미연결 광고 중 / 연결 중 / 사용 중)로 폰 앱에 **보이는지** → 연결 중 이어폰이 안 보이면 시뮬레이션의 BLE 가정이 낙관적이라는 뜻.
2. 거리(1·3·5·8 m)별 RSSI → 경로손실 지수와 음영 분산 실측값으로 `sim/engine.js` 상수 교체.
3. 복도→교실 벽 감쇠(dB), 사람이 가릴 때 감쇠.
4. 폰 Wi-Fi 스캔 갱신 주기(OS 제한), BLE 보고 빈도, 단말별 RSSI 편차.

## 알려진 한계
- 셀룰러(LTE/5G) 송신은 볼 수 없다 → 스마트폰 AI 질의의 주 경로는 놓친다.
- 연결 중인 BLE/Wi-Fi 기기의 통신은 일반 폰으로 볼 수 없을 수 있다(광고/비콘/AP 신호만 관측).
- 안드로이드 Wi-Fi 스캔은 OS가 횟수를 제한한다(9+: 2분에 4회). BLE는 상대적으로 촘촘하다.
- 기기 주소 무작위화(MAC randomization)로 같은 기기가 다른 ID로 보일 수 있다.
- 위치는 감독관이 직접 누른 태그 기반이라 그 정확도가 결과를 좌우한다.
- iOS는 지원하지 않는다.
