# 수능 시험장 AI 부정행위 전파 탐지 — 제안 요약

> 상태: 1단계(시뮬레이션) 완료. 아래 수치는 모두 **가정 기반 시뮬레이션 값**이며 실측 성능이 아니다.
> 데모: 저장소의 `sim/` (브라우저에서 열림). 검증: `node sim/test.mjs`.

## 1. 문제와 목표

수능에서 스마트폰·무선 이어폰·스마트워치·스마트안경 등에 AI를 연결해 문제를 푸는 부정행위가 우려된다.
목표는 **시험 중 전파를 내는 숨겨진 기기의 존재와 대략적 위치(좌석 단위 확률)를 감독관에게 알려, 확인 행동을 돕는 것**이다.
자동 판정이나 학생 지목 수단이 아니라 *감독관 보조 도구*로 설계한다.

## 2. 접근: 단계적 도입

| 단계 | 내용 | 설치 | 상태 |
|---|---|---|---|
| 1 | 가상 교실 시뮬레이션, 센서 구성 비교 | 없음 | 완료 |
| 2 | 모의시험 현장 실측으로 신호 모델 보정, 감독관 폰 앱 프로토타입 | 폰 6대 | 제안 |
| 3 | 소규모 고정 센서(4~8개) + 현장 캘리브레이션 + 폐쇄망 대시보드 | 교실당 센서 | 제안 |
| 4 | 시범 운영 (모의평가 등, 승인 하에) | | 제안 |

## 3. 감독관 폰 활용안 (교실 3명 + 복도 3명, 이동 가능)

감독관은 시험 중 폰으로 다른 작업·외부 통신을 해서는 안 된다(문제 유출 방지). 따라서 다음을 **설계 요건**으로 둔다.

- 전용 앱은 **인터넷 권한을 선언하지 않는다**(안드로이드 `INTERNET` 권한 없음 → 앱이 외부로 데이터를 보낼 수 없음). 폰은 비행기 모드 + 수신만 허용.
- 수집 항목은 신호 세기·시각·해시 처리된 임시 식별자뿐. 통신 **내용은 수집하지 않으며**, 문제 정보와 무관.
- 데이터는 단말에 저장 후 시험 종료 시 회수·분석하거나, 인터넷에 연결되지 않은 현장 폐쇄망(허브 노트북)으로만 전달.
- 감독관은 앱 화면의 알림만 확인하고 다른 앱은 사용하지 않는다(키오스크 모드 권장).

## 4. 시뮬레이션 결과 (`node sim/test.mjs`, 30회 평균)

기기 탐지율 / 위치 정확도 (좌석 간격 2.0 m × 1.1 m):

| 센서 구성 | 스마트폰 LTE | 이어폰 BLE | 워치·안경 BLE/Wi-Fi |
|---|---|---|---|
| 고정 8개 (보정 안 함) | 탐지 100% / 1.07 m | 탐지 100% / 1.07 m | 탐지 100% / 1.03 m |
| 고정 8개 + 현장 캘리브레이션 | 탐지 100% / 0.42 m | 탐지 100% / 0.44 m | 탐지 100% / 0.50 m |
| 감독관 폰 6대 (순찰) | **탐지 0%** | 탐지 50%\* / 0.51 m | 탐지 100% / 0.70 m |
| 감독관 폰 6대 (제자리) | **탐지 0%** | 탐지 50%\* / 1.69 m | 탐지 100% / 1.35 m |
| 혼합 (고정 4 + 폰 6) | 탐지 100% / 1.45 m | 탐지 100% / 0.69 m | 탐지 100% / 0.91 m |

\* 이어폰 시나리오의 부정행위 기기 2대(이어폰 BLE + 연결 폰 LTE) 중 BLE만 탐지되어 50%.
오탐(정상 시험에서 감독관 석 외 경보): 모든 구성 0/30.

### 시사점
1. **폰만으로는 셀룰러(LTE/5G)를 볼 수 없다.** 스마트폰 AI 질의가 가장 흔한 경로이므로 폰 단독 구성은 핵심 위협을 놓친다.
2. **감독관이 순찰하면 정확도가 크게 오른다**(제자리 1.35 m → 순찰 0.70 m, 워치·안경 기준). 여러 위치에서 측정해 음영 오차가 평균되기 때문이다.
3. **폰이 자기 위치를 얼마나 정확히 아는지가 결정적이다.** 위치 오차 ±0.5 m에서 0.6~0.7 m, ±1.5 m에서는 1.5 m 이상으로 악화(고정 센서보다 나쁨). 좌석 마커 스캔 등 위치 보정 수단이 필요하다.
4. **고정 센서 소수 + 현장 캘리브레이션 + 감독관 폰 보조**가 비용 대비 가장 현실적인 조합으로 보인다(실측 검증 필요).

## 5. 한계와 검증이 필요한 가정

- 시뮬레이션은 폰/센서가 블루투스·Wi-Fi 송신을 직접 수신한다고 가정한다(**낙관적**). 실제 일반 폰은 광고(비콘) 신호만 보며, **이미 연결된 이어폰의 통신은 직접 볼 수 없을 수 있다.** 전용 스니퍼 하드웨어 또는 모의시험 실측이 필요하다.
- 안드로이드 Wi-Fi 스캔은 OS가 횟수를 제한한다. iOS는 Wi-Fi 스캔 불가, 블루투스 제약 큼 → **안드로이드 단말 기준**.
- 전원이 꺼진 기기, 수신 전용 기기는 탐지 불가. 송신 활동량과 패턴으로 AI 사용을 *추정*할 뿐, 파일 내용·전송량·방향은 알 수 없다.
- 복도 폰은 벽 감쇠(가정 9 dB) 너머로 듣는다. 실제 건물 구조별 값이 필요하다.
- 신호 모델 상수(경로손실 지수, 음영 3.5 dB 등)는 가정이며 현장 실측으로 교체해야 한다.

## 6. 운영 원칙과 승인 사항

- 경보는 "어느 구역을 확인하라"는 단서이며 **부정행위의 증거가 아니다.** 지목 전 감독관 육안 확인·규정 절차를 따른다.
- 재밍(전파 차단)은 사용하지 않는다(전파법).
- 필요 승인: 한국교육과정평가원·교육청 협의, 개인정보 영향 검토, **통신비밀보호법 검토**(통신 내용 비수집, 신호 메타데이터만 사용함을 명확히), 감독관 교육, 학생 사전 고지.

## 7. 다음 단계 제안

1. 모의평가 시험장 1곳에서 실제 기기(스마트폰·이어폰·워치)로 신호 실측 → 모델 보정, 위 가정 검증.
2. 안드로이드 감독관 앱 프로토타입(인터넷 권한 없음, 단말 저장, 위치 보정).
3. 고정 센서 4~8개 + 폐쇄망 대시보드로 소규모 시범 운영 계획 수립.
